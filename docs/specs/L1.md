# L1 - High-Level Requirements

**Scope:** Augur is a command-line code generator. It reads a natural-language specification (text and optional images), uses the OpenAI Decisions API to choose among a fixed set of generation options, records those choices in a `GenerationPlan`, and emits code from that plan without any model involvement. Augur can emit a fullstack application (a .NET API solution and an Angular workspace wired together), a .NET solution on its own, or an Angular workspace on its own.

**Out of scope for this release:** generating entities, fields, or business logic from free text; user-defined decision catalogs; output targets other than .NET and Angular; a graphical user interface for Augur itself.

## L1-001: Command-line interface
The system shall be a cross-platform command-line tool that lets a user produce a generation plan from a specification, emit code from a plan, do both in one step, and inspect the decisions behind a plan. Every command shall report its outcome through documented exit codes and keep machine-readable output separate from diagnostic messages.

## L1-002: Specification input
The system shall accept a natural-language specification as text, optionally accompanied by images, and shall reject input that is missing, empty, malformed, or larger than documented limits before any decision is made.

## L1-003: Decision catalog
The system shall ship a versioned catalog that defines every decision it can make, the closed set of possible answers for each decision, a description of when each answer applies, and a safe default. The catalog shall be inspectable by the user.

## L1-004: Behaviour-tree decision evaluation
The system shall evaluate the decision catalog as a behaviour tree, asking the Decisions API only for decisions that cannot be settled deterministically, respecting dependencies between decisions, and never accepting an answer that is outside the decision's closed set of answers.

## L1-005: Decisions API integration
The system shall communicate with the OpenAI Decisions API reliably, batching independent questions, handling transient failures, enforcing time limits, and rejecting malformed responses.

## L1-006: Confidence thresholds and fallbacks
The system shall detect when the Decisions API is not confident enough about a decision and shall resolve that decision through a user-selected policy: use the catalog default, ask the user, or fail.

## L1-007: Reproducible decisions
The system shall record every resolved decision in a lockfile so that re-running the same specification produces the same decisions without calling the Decisions API, and shall re-ask only the decisions whose input or definition has changed.

## L1-008: Generation plan
The system shall represent the complete set of resolved decisions as a versioned, human-readable `GenerationPlan` that can be saved, inspected, edited by hand, validated, and used as the sole input to code emission.

## L1-009: Deterministic code emission
The system shall turn a valid `GenerationPlan` into a fullstack application, a .NET solution, or an Angular workspace, as the plan's target requires, that builds and passes its own tests, produce identical output for identical plans, and never damage files the user did not ask it to replace.

## L1-010: Offline and scripted operation
The system shall be able to run without network access by using only recorded decisions, and shall be able to take decisions from a scripted answer file so that it can run in continuous integration and automated tests without the Decisions API.

## L1-011: Observability
The system shall explain how every decision was reached, report what it did during a run, and provide adjustable diagnostic logging, without exposing secrets.

## L1-012: Security
The system shall protect the user's API credentials, protect the user's file system, limit what data leaves the machine, ensure model output can never inject content into generated code, and generate code that follows secure defaults.

## L1-013: Performance
The system shall minimize Decisions API round trips and complete runs quickly and within bounded memory, especially when decisions are replayed from the lockfile.

## L1-014: Distribution and platform support
The system shall be distributed as a .NET global tool that installs and runs on Windows, Linux, and macOS.

## L1-015: Generated user interface quality
The system shall generate Angular user interfaces that work across all viewport sizes, from small phones to large desktop screens, and that are accessible to keyboard and assistive-technology users.
